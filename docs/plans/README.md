# 기획 및 설계 문서 관리

이 폴더는 ITSM 설계 에이전트의 제품·요구사항·기능·기술 기준과 백엔드 구조안을 관리한다. 문서는 목표 계약이며 구현 현황은 [프로젝트 README](../../README.md)와 현재 작업 계획에서 확인한다.

## 변경 시 함께 확인할 문서

| 변경 종류 | 주 기준 문서 | 영향 확인 |
| --- | --- | --- |
| 사용자·목표 제품 MVP 범위·성과 목표 | PRD | 요구사항, 평가 계획 |
| 필수 동작·수용 기준 | 요구사항 정의서 | 기능 명세서, TRD, 테스트 |
| 입력 제한·상태·예외·다운로드 정책 | 기능 명세서 | 요구사항, TRD, UI·API |
| API·DB·스키마·기술 구성 | TRD | 기능 명세서, 코드·테스트 |
| 백엔드 파일 책임·명명·첨부 로직 배치 | 백엔드 통합 구조와 명명 규칙 | TRD, 통합 작업 계획, 계층 테스트 |

특히 입력 상한, 실행 상태, 재시도 횟수, DDL 검증 및 다운로드 규칙은 문서 간 값이 일치하는지 확인한다. 현재값의 상세 기준은 기능 명세서이며, 기술 구현은 TRD에서 설명한다. 실제 구현과 다르면 TRD 또는 실행 계획에 기록하고 계획을 실적처럼 수정하지 않는다.

## 개발 실행 계획

- [004 첨부 핵심 로직과 제품 흐름 통합](tasks/004-첨부-핵심-로직-통합.md): 진행 중 (1.0, 2026-10-16) — 현 4단계 그래프의 파일 분리와 A의 새 스키마·순수 검사·전이 계약은 테스트를 마쳤다. A 코드는 현 그래프에는 연결되지 않았다. 전문 역할 통합, 문서/실행 저장, 웹 UI, 격리 DB 검증·평가는 후속 작업이다.

여러 단계가 필요한 기능 개발은 `docs/plans/tasks/`에서 `NNN-작업명.md` 형식으로 계획한다. 단순 문구 수정은 별도 계획이 필요 없다. 아직 시작하지 않은 구현을 완료 체크하지 않는다.

작업 계획에는 다음 내용을 기록한다.

- 상태: 예정 / 진행 중 / 대기 / 완료
- 목적, 범위와 제외 범위
- 관련 FR·NFR·AG ID 및 문서 링크
- 구현 단계와 실제 진행 체크리스트
- 검증 방법, 실행 결과, 남은 문제
- 업무·기술 결정과 이유, 관련 기준 문서의 갱신 여부

완료한 작업의 실행법은 README와 시나리오 안내에 남기고, 과거 계획·검증 상세는 Git 이력으로 확인한다. 기획·설계의 결정은 기준 문서에 반영하고 진행 중인 계획에는 결정 이유와 구현 증거를 남긴다.

## 향후 폴더 확장

실제 자료가 생길 때만 다음 폴더를 추가한다.

- `docs/evaluation/`: 평가 절차, 실측 결과와 실패 분석
- `docs/decisions/`: 여러 대안을 비교한 중요한 기술·업무 결정
- `docs/plans/tasks/`: 기능별 구현 계획과 진행 기록

생성한 고객 설계 결과나 평가 입력은 기준 문서 폴더에 섞지 않는다. 실행 결과 저장 위치는 앱 설정과 TRD를 따른다.
