## 범위와 진행 원칙

현재 `/api/v1/design`의 동기 텍스트 API, Anthropic 호출, 공통 모델 검증·ERD/DDL 렌더러와 테스트를 출발점으로 삼는다. 첨부 소스의 파일·패키지·설정·스키마를 통째로 옮기지 않고 [구조 문서의 배치 판단](../백엔드_통합_구조.md)에 따라 필요한 알고리즘과 테스트 사례를 이식한다. 운영 DB는 프로젝트·문서·실행을 저장하고, 고객용으로 생성한 DDL은 격리 검증 DB에서만 실행한다.

첫 리팩터링에서 현재의 `generate → validate → render → review`를 `design_pipeline/`의 그래프·상태·모델 호출·역할·검증/변환 노드로 분리했다. API 입출력과 4단계 분기는 유지했다. 이는 첨부 소스의 전문 역할 이식이나 문서/실행 저장 기능을 완료한 단계가 아니다. 분리된 각 파일은 [구조 문서의 현재 트리](../백엔드_통합_구조.md)를 따른다.

이번 통합의 목표는 PDF·DOCX·UTF-8 TXT 입력, 근거 확인, 질문과 답변, 기능·데이터 설계, 공통 모델의 ERD·DDL, 추적·검토, 실행 상태와 산출물 제공, 웹 UI 연결이다. HWPX·Markdown·CP949 입력 지원, CLI·manual LLM 공급자, SQLite로 PostgreSQL 성공을 대신하는 경로, 범용 변경 요청의 부분 재설계는 범위에서 제외한다. 후속 범위가 필요해지면 먼저 PRD·요구사항·기능 수용 기준을 변경한다.

작업은 아래 순서와 선행 조건대로 진행한다. 각 묶음은 관련 코드·필요한 기준 문서·테스트를 같은 변경에서 다루고, 현재 API를 바꾸는 시점은 계약 검사 통과 뒤로 둔다. `추가 예정` 파일 경로는 생성 계획일 뿐 구현 실적이 아니다.

## 역할별 작업 배치

## 이식 전 필수 실패 사례

첨부 소스에서 재현한 아래 동작은 통합 결과의 수용 조건으로 삼지 않는다. 담당 작업에 회귀 테스트를 추가해 차단한다.

| 담당 | 재현 조건 | 기대 결과 |
| --- | --- | --- |
| B·C | 한 본문 추출 배치가 실패하고 다른 배치가 성공 | 실패 단위와 원인이 남으며 전체 실행을 성공으로 표시하지 않는다. |
| B | 같은 절에 요구사항 표와 표 밖 의무 문장이 함께 있음 | 두 부분이 모두 추출 대상 또는 명시적 미추출 경고로 남는다. |
| B | 원문 `1.5초`, 생성 인용 `15초` | 근거 불일치로 검출한다. |
| C·D | 변경 기능에 새 입력 컬럼이 필요한데 기존 엔티티에만 연결됨 | 모델 속성 재검토 없이 최신·완료 판정을 하지 않는다. 부분 재설계를 지원하기 전까지는 새 실행에서 전체 재생성한다. |
| C | 비기능 요구사항의 보관 기간에 사용자가 답함 | 답변이 기능·데이터 설계 입력 및 결과 검토에 나타난다. |
| D·F | 모델에 존재하지 않는 FK 대상이 있음 | DDL에서 FK가 사라져도 구조 및 DB 검증이 통과하지 않는다. |
| E·F | DB 검증 실패 또는 산출물 저장 실패 | 성공·배포 가능 파일로 기록하거나 실패한 DDL을 다운로드하지 않는다. |
| F | DB 검증 환경 장애로 미실행 | `not_run`과 경고를 기록하고 SQL은 ‘미검증 초안’으로만 제공한다. 검증 성공으로 집계하지 않는다. |

## 현재 구현의 회귀 기준

기존 4단계 그래프를 대표 시나리오 3종으로 실제 호출했을 때 01 헬프데스크는 완료, 02 장애 대응은 `review`의 원문 인용 불일치(502 `invalid_review_reference`), 03 서비스 카탈로그는 추가 테이블의 PK·추적 누락(422 `structure_invalid`)으로 끝났다. 당시 모델은 `claude-haiku-4-5-20251001`, 출력 한도는 8192토큰이었다. 이 실측은 현재 버전의 일반 성공률이 아니라 단계 분리·오류 복구의 회귀 사례다. A·C에서 현 4단계의 입출력을 새 전문 역할로 나눌 경계를 정하고, 제한된 재시도 규칙은 한 그래프 경로에만 구현한다. 검증 규칙을 완화하거나 실패를 샘플 출력으로 대체하지 않는다.

현재 백엔드 동작과 첨부 저장 응답 재생은 각각의 기존 범위에서 얻은 증거다. 신규 통합의 동작·품질 통과로 이월하지 않는다. 작업별 기록에는 실행 명령, 통과/실패, 실제 LLM·격리 DB 미검증 범위, 변경한 파일과 관련 문서 버전을 남긴다.
