# 백엔드 MVP 실행 계획

- 버전·최종 수정일: 0.3 · 2026-10-07
- 상태: 완료
- 범위: 사용자 요청으로 확정한 이번 백엔드 범위. 전체 제품 문서는 장기 목표로 유지한다.
- 기준: [TRD](../TRD.md), [요구사항](../요구사항_정의서.md), [기능](../기능_명세서.md)

## 구현 계약과 수용 조건

`POST /api/v1/design`에 JSON `text`(공백 제외 비어 있지 않음, 원문 최대 12,000자)를 보내면 한 요청에서 LangGraph의 generate → validate → render → review를 실행한다. 정상 LLM 호출은 Anthropic 2회, 호출당 기본 120초, SDK 재시도 0회다. 구조 오류면 render/review 없이 422로 실패한다. 생성·검토 모델 오류는 502, 시간 초과는 504, 키 미설정은 503이다. 오류는 기존 `code/message/detail` 형태를 따른다.

반환 대상은 요구사항·원문 인용, 기능 명세, 공통 모델, Mermaid ERD/PostgreSQL DDL 문자열, 요구사항↔기능↔테이블 추적표, 누락·모순·질문이다. 구조 검증과 의미 검토를 구분하고 DB 실행은 항상 `not_run`, 산출물은 미검증 초안이다. 의미 검토는 사람이 판단할 후보이며 자동 수정하지 않는다.

관련 장기 요구사항: FR-004~006, FR-008~014, FR-019; NFR-001, 005, 008~012; AG-02, 04~08. FR-005는 원문 문자열 인용 일치만, FR-011은 미실행 표시만, FR-012는 테이블 단위 연결만 구현한다. 장기 사양 전체 충족을 뜻하지 않는다.

자료형은 integer/bigint/text/boolean/date/timestamptz/uuid로 제한한다. 테이블당 단일 PK, 컬럼 단위 UNIQUE·NULL·단일 FK만 지원한다. FK는 같은 타입의 PK/UNIQUE를 참조한다. SQL 식별자는 ASCII 소문자·숫자·밑줄 63자 이내이며 항상 인용한다. 복합 키·CHECK·기본값·인덱스·삭제 정책·자유 SQL은 제외하고 필요한 업무 규칙은 기능 명세와 확인 사항에 기록한다.

Langfuse는 자격증명 없으면 비활성화한다. 기본 전송은 단계·시간·모델·토큰·오류 코드뿐이며 원문·프롬프트·생성 본문은 보내지 않는다. SDK 오류는 본 흐름을 중단하지 않는다. 캐싱 요청과 캐시 실제 사용량을 별도 반환한다.

## 제외

프론트엔드, 프로젝트·파일·결과 저장, 업로드·다운로드·인증 API, 대화형 답변, 작업 큐/워커/상태 조회, DB 접속 및 생성 DDL 실행, RAG/Redis/벡터 DB, 공급자 추상화, 체크포인터·메모리·멀티에이전트·서브그래프·자동 수정 루프.

## 실제 검증 기록 (2026-10-07)

- `cd backend && .venv/bin/pytest -q`: 47개 통과. 모델 HTTP 전송을 대체하고 실제 SDK 직렬화·4단계 그래프·구조 검사·ERD/DDL 변환을 실행했다.
- 주요 시나리오: 서비스 요청·장애 연결, 이력 누락 검토 후보, 저장 불필요, 잘못된 참조·ID 중복·추적 누락·원문 불일치·PK/FK/타입/식별자 오류, 잘못된 JSON, 생성 잘림·거부·외부 오류·시간 초과, 검토 형식·참조 실패, 명령 형태 원문을 데이터로 전달, 추적 오류 격리.
- `.venv/bin/ruff check .`, `.venv/bin/ruff format --check .`, `pip check`: 통과.
- 격리된 `postgres:16-alpine` 컨테이너(127.0.0.1:55439)에서 기존 Alembic `upgrade head`/`downgrade base` 통과. `TEST_DATABASE_URL=postgresql+psycopg://app:app@127.0.0.1:55439/app .venv/bin/pytest -q`도 통과. 이는 기존 기반 코드 검사이며 고객용 생성 DDL은 실행하지 않았다.
- `uvicorn app.main:app --host 127.0.0.1 --port 8017`: DB 초기화 없이 시작. 실제 HTTP `/health` 200, 빈 설계 입력 422 확인.
- Langfuse 공식 SDK에 메모리 exporter를 연결한 자동 검사: 같은 trace의 design/generate/validate/render/review 5개 span, 모델 사용량·시간 기록 확인. 원문·프롬프트·생성 본문·예외 이벤트 없음. 별도 오류 주입에서 초기화/start/update/end 실패에도 설계 완료.
- **Langfuse 원격 연동 미검증**: 자격증명 없음. 추적 활성화는 원격 수신 성공을 뜻하지 않는다.
- **실제 Anthropic 전체 흐름 확인**: 아래 실측 참조. 실제 모델 실패를 성공 또는 샘플로 대체하지 않았다.
- 검증 환경: Python 3.12, Anthropic 0.125.0, LangGraph 1.2.14, Langfuse 3.15.0. 세 신규 직접 의존성 버전을 고정했다.

## 남은 제한

의미 품질·캐시 적중·Langfuse 원격 수신과 생성 DDL DB 실행은 자동 테스트 결과로 대체하지 않는다. 모델 출력 2048토큰은 짧은 입력에도 설계 크기에 따라 부족할 수 있다. 구조 오류나 토큰 초과를 자동 수정·재시도하지 않는다.

## 실제 Anthropic 실측

모든 실행의 입력은 “사용자가 제목을 입력해 서비스 요청 또는 장애를 등록하고 유형과 제목을 저장한다.”이다. 모델 `claude-haiku-4-5`, 출력 2048토큰, 캐싱 true를 유지했다. 입력 범위나 모델 설정은 변경하지 않았다. 매 실행 정상 호출 경로는 generate/review 2회였으며 앱의 자동 재시도는 없다.

캐싱은 설정만 활성화됐고 실제 적중은 없었다. 전체 5회 중 성공 3회·검토 검증 실패 2회이며, 소규모 개발 중 반복 실행으로 일반 정확도·신뢰도 수치로 해석하지 않는다. 의미 검토는 후보이고 사람이 확인해야 한다. 최종 코드 자동 테스트 47개·ruff 검사 통과. 임시 서버와 테스트 DB 컨테이너는 검증 후 종료했다.
